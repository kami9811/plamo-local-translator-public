# 通信とセキュリティの確認範囲

通信境界はv0.1.4で補強し、v0.1.5でも維持しています。モデル取得の修正と実モデル再試験は[モデル取得の検証](MODEL-DOWNLOAD.md)を参照してください。独自アプリの通常の翻訳経路はPC内で処理し、クラウド翻訳・利用状況送信・自動更新を実装していません。PC/Chrome全体の通信禁止や、脆弱性が存在しないことを保証するものではありません。

| 操作 | 接続先・データ |
| --- | --- |
| 通常の選択文・ページ・原稿翻訳 | 拡張→127.0.0.1:8765→127.0.0.1:8766。本文はローカルAPIと推論エンジンへ渡す |
| 接続キーの表示 | WSL/ローカルPythonから、このプロジェクトのローカルAPIを確認。コントローラーの設定ファイルやログへキーを保存しない |
| フォント | 拡張に同梱。フォント配布サービスへの通信なし |
| モデル・ランタイム・開発依存の初回取得 | GitHub / Hugging Face / Node.js / npm等へのダウンロード通信。本文は取得処理に渡さない |
| 「手順を見る」等の案内リンク | 利用者の操作でブラウザーがGitHub等を開く |
| 閲覧中のWebサイト、ChromeやOS | それぞれ通常の通信を行い得る。本アプリの通信制御とは別 |

ページ内の吹き出しや全文翻訳は、閲覧先ページのDOMへ訳文を表示します。サイト側のJavaScriptがDOMの変更を読み取る場合があり、そのサイト自身の送信処理を本アプリで禁止する仕組みではありません。機密の原稿は、拡張の原稿ワークスペースで扱ってください。

## v0.1.4で補強したこと

- 推論APIへのPython通信は環境プロキシを使わず、HTTP転送に追従しない。以前の標準urllibでは、プロキシ設定がある場合に経由できた。流出の発生を確認したという意味ではない。
- 拡張のContent Security Policyは同梱リソースと指定したループバックAPIを許可。アプリのfetchは転送をエラーにする。接続先の文字列検証も行う。
- llama.cppを明示的なオフラインモード、エージェント/外部MCPプロキシ無効で起動。外部設定のLLAMA_ARG_*やプロキシ、HF_TOKEN等を子プロセスへ引き継がない。
- 推論用キーは0600のファイルで渡し、プロセス引数へ含めない。APIの起動ログへ接続キーを表示しない。端末に表示する場合は利用者がscripts/start.pyを実行したときだけ。
- ブラウザー画面の自動キー配布（bootstrap）を廃止し、HTTPブラウザー版でもキー入力を必須にする。Origin等のヘッダーを偽装したローカル要求へキーを渡さない。
- APIは127.0.0.1で待ち受け、Host/Originを検証し、保護APIはBearerキーを必須とする。原稿や訳文はtextContent等で表示し、HTMLとして実行しない。
- 原稿・訳文・キャッシュはローカルの.data/へ保存する。暗号化保存ではない。Unixではデータディレクトリ0700、キー/SQLite0600を設定する。

## 検証の区別

Pythonの隔離HTTPサーバーで、従来の標準通信がプロキシのテスト用サーバーを経由することを再現し、修正後は経由しないことを確認。転送先に到達しないこと、Host/Origin/認証の拒否、推論の起動引数とキーの扱いも確認する。テストには合成文とテスト用キーだけを使う。

Chromeの隔離プロファイルでは模擬APIを使い、拡張のfetch先、CSPによる外部送信拒否、転送先に追従しないこと、HTML文字列を文字として表示することを確認する。実モデルの通信やPC全体のパケットを捕捉した検証とは区別する。ブラウザーのプロキシ設定やOS/拡張・依存バイナリの改変までOSのファイアウォールで封じる仕組みではない。

llama.cppのオフライン指定は固定したb12121の公式ソースと、公式バイナリの引数解析で確認する。外部モデル取得・ツール実行は必要ない構成にし、初回取得後の推論に外部サービスを前提としない。

## 既存環境の更新

操作アプリ0.1.1はそのまま使えます。通信制限を適用するのは翻訳環境のPythonコードとChrome拡張の両方です。使っているフォルダーを自動で書き換えたり、APIを勝手に再起動したりしません。

1. 利用者が操作アプリで「停止」を押す。
2. 変更のない作業ツリーで、翻訳環境をv0.1.5へ更新する。ローカル変更があれば先に保護する。

   ```bash
   git fetch origin --tags
   git switch --detach v0.1.5
   scripts/node.sh npm ci
   scripts/node.sh npm run build
   ```

3. ビルドしたdist、またはv0.1.5の拡張ZIPの内容で、Chromeに読み込んだ拡張フォルダーを更新する。chrome://extensionsで「再読み込み」を押す。
4. 操作アプリで「起動」を押し、必要なら接続キーを再登録する。

.data/や.runtime/を削除する必要はありません。旧版のログには起動時の接続キーが記録されている場合があるため、ログを公開しないでください。v0.1.4は既存ログを自動削除しません。

## v0.1.4再検証時の取得問題（履歴）

この節は旧版の検証記録です。v0.1.5では取得可能な公式固定版へ更新しています。原因と再試験は[モデル取得の修正](MODEL-DOWNLOAD.md)を参照してください。

Macの実モデル再試験は、Hugging Faceのモデル配布先がHTTP 403を返し、取得段階で停止した。公式の公開メタデータではモデルは公開・非gatedで、固定リビジョンの2BのSHA256も一致している。取得制限を回避するために非公式の重みやミラーを使っていない。

そのため、v0.1.4で2B/8Bを再度生成した結果とは扱わない。取得済みの重みはそのまま使い、更新時の再ダウンロードは不要。通信制御は隔離したテストと、モデルをロードしない公式ランタイムの引数解析で検証する。新規モデル取得が必要な場合は、この配布先の状況に影響される。

検証記録：[通信境界の結果](validation/network/summary.json)、[Mac CI](https://github.com/kami9811/plamo-local-translator-public/actions/runs/42185695591)。両Macで成功。
