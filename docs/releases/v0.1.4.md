# v0.1.4 — 翻訳時の通信制限を補強

通常の翻訳経路をPC内へ限定する制限を追加しました。修正は翻訳環境とChrome拡張の両方に入っています。操作アプリ0.1.1はそのまま使えます。

| 操作 | 通信 |
| --- | --- |
| 選択文・ページ・原稿の翻訳 | PC内APIと推論エンジン |
| モデル・依存関係の初回取得 | GitHub / Hugging Face / Node.js / npm等 |
| 「手順を見る」等のリンク | 利用者の操作でGitHub等を開く |

- Pythonの推論通信を環境プロキシなし・HTTP転送拒否に変更。
- 拡張のCSPで接続先を制限し、fetchも転送を拒否。
- llama.cppのオフライン実行を明示し、環境由来のエージェント・外部MCPプロキシ等を無効化。
- 推論キーを0600ファイルへ移し、プロセス引数に含めない。API起動ログへのキー出力も削除。
- HTTP原稿画面の自動キー配布を廃止し、ブラウザー版でも明示的なキー入力を必須化。通常の拡張は従来どおり一度登録する。

[通信範囲・検証結果・更新手順](https://github.com/kami9811/plamo-local-translator-public/blob/main/docs/NETWORK-SECURITY.md)

PythonはPublic20件/Private17件、隔離Chromeで模擬APIを使う通信境界テストは両方成功。Linux/WSLと両Macの固定ランタイムで引数解析を確認。両Macで実APIの起動・キー表示・停止も確認。ユーザーの実API・モデルは起動していません。

2B/8Bの実モデル再試験は、公式モデル取得先のHTTP403で取得段階に止まりました。生成に成功した扱いにはしていません。取得済みの重みは更新時に取り直す必要がありません。新規モデル取得が必要な場合は配布先の状況に影響されます。

クラウド翻訳・利用状況送信・自動更新は実装していません。Chrome・閲覧先サイト・OSの通信を全面的に禁止するソフトではなく、PC全体のパケット検査や脆弱性不存在の証明も行っていません。ページに表示した訳文は閲覧先サイトのJavaScriptが読める場合があります。

更新時は、利用者がAPIを停止してから翻訳環境をv0.1.4へ更新し、拡張ZIPの内容を置き換えてChromeで再読み込みしてください。既存の.data/と.runtime/を削除する必要はありません。
